# Artisanal construction and selective augmentation

KPP is the creator's development practice supported by executable protocol tools.
The Baker can be a human, AI, or collaboration. A Taster evaluates; the Baker
remains responsible for scoped acceptance. Manual attestation means an explicit
externally supplied decision, not a requirement that the actor be human. Existing
host permissions still govern actions. A model proposal or label is no grant.

The dependable OVEN is an engineering assumption for a bake, not certification
that a model never fails. Small batches refine a recipe until the Baker accepts
the Cake. Preserve accepted source, dependencies, environment, commands and test
evidence for repeatable builds. Replaying AI construction steps alone does not
guarantee identical source or reproducible outputs. Later batches need fresh checks.

Recipe/4 optionally declares `construction: {"techniques": []}` for dependency-ready
requirements in recipe order, or `construction: {"techniques": ["chase"]}` for
activity/depth-prioritized Chase. Omission preserves legacy Chase ordering.
Recipe/3 remains unchanged. The `next` command and `views.chase` compatibility
alias report the selected ordering; graph/build-step/plan/handoff report its basis.
Selection changes recipe identity and cannot reuse an old workspace's acceptance.
The target describes the desired product/reference; it does not itself select Chase.

Evaluate augmentation before converting a mature application. Keep native user
operations and optional MIND operations on the same tested functions. Verify each
sensor/action pathway individually, failures, permissions and host behavior with
the MIND absent. SCAN discovers bounded structure; it does not prove complete
control, semantic equivalence or arbitrary-language conversion. Anchor profiles
remain optional and qualified. The creator reports complexity limits in earlier
Anchor experiments; that is a research observation, not a measured universal limit.

Finished Cakes need only the runtime components required by their recipes; KPP
need not remain a runtime dependency. An AppAI is resident in its host/NEST; an
Engram can travel in a cartridge or PNG carrier. Decoding requires original bytes
and a compatible authorized host; upload alone is not activation or permission.

The synthetic augmentation walkthrough runs with no provider and uses the shared
Body, optional cognition, checked effects and transaction mechanisms. Run:
`python -m mantleos.augmentation --output UNUSED_DIRECTORY`.
Its report pins host/adapter source, maps individual read/edit/save operations,
and records actual outcomes. It is bounded qualification, not complete Hermes parity.
Its workspace remains BUILDING with no acceptance. Original source is retained.

The supplied chat logs describe other experimental snapshots. Their reported
arms startup defects, concurrent PNG writes and permission/privacy concerns are
unverified leads for those snapshots. No private identity or history is imported.
Logical append-only history preserves prior records even when a carrier file is
rewritten; hashes detect drift but do not make storage physically immutable.

MantleOS's capability-multiplier objective is a research hypothesis. Model rankings,
live comparisons, universal conversion and automatic scaling are unmeasured here.
Existing representative missions copy founding PRIMER bytes into a distinct child,
with separate identity and experience. Returned findings await explicit review
and append-only admission; they do not transfer authority or parent identity.
