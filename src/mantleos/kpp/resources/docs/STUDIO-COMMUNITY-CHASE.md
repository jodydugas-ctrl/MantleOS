## Contract and discovery

`tools/studio_chase_inventory.py --source PINNED_CHECKOUT --output NEW_DIRECTORY`
checks exact committed bytes before projecting explicit command declarations
into a draft recipe/4. It records command symbol, file, line, source digest and
dynamic-factory limitations. It does not execute or relicense n8n source.
The first projection found 80 declarations in 16 inspected files, including the
workflow, node/context, execution, navigation, help and settings command families.
This is not an exhaustive inventory of Community user functions. Dynamic
children, every node's operations/parameters, dialogs, settings, credential
variants, entitlements and actual runtime states still need reconciliation.

The generated recipe owns the requirements. The source inventory is discovery
data without acceptance state. A mandatory Community scope-review gate prevents
80 static declarations from being treated as the complete product. Every draft
command obligation requires handler/child review, enablement guards, valid and
invalid input, confirm/cancel, direct effects, undo where applicable, save/reload,
permission/error cases and preserved interacting behavior. No mandatory function
is removed because its implementation or external test account is unavailable.

Existing canonical applications cover command input, workflow state, host
coordination and contract boundaries. Increasing depth adds consequences and
cases, not invented singularities, opcodes or a mandatory number of applications.
The inherited numeric Fidelity declaration is retained; depth 5 on these new
obligations describes their declared tests, not a universal certification tier.

## First executable slice: strict IF

The optional Node-RED palette now includes **If (strict)** in Anchor Studio
automation. It is executing JavaScript tissue, separate from the inert Anchor
design nodes. Its parameter dialog edits typed conditions, AND/OR, case handling
and continue-on-failure. Deployment is an explicit native editor action; importing
a design or model proposal never deploys it.

Input `msg.payload` is a JSON array of `{json: {...}}` items. The independent
`studio.if/1` adapter supports number/string/boolean comparisons, existence/empty
checks, string containment/prefix/suffix and ordered numeric comparisons.
It preserves source item order and existing item pairing, adds pairing when
missing, and emits only populated true/false branches. Strict evaluation errors
send no partially computed branch output and use the ordinary Node-RED Catch
boundary. Explicit continueOnFail routes invalid items to false with indexed
errors. Following filter version 4, numeric empty strings (including whitespace)
and empty arrays normalize to null before strict type validation. Nonempty
numeric strings still fail strict validation. The adapter permits at most 32 conditions, 128 items, 256 KiB input and
32 JSON nesting levels. These are implementation bounds, not Anchor rules.

This is not an n8n JSON importer or a full n8n IF implementation. Arbitrary
expressions, type conversion, regex, date/array/object operators and other node
versions remain unsupported; they stay within the unfinished broader chase.
Source inspection supplies the semantic reference. The optional matched probe
executes the actual published `n8n-workflow@2.46.4` filter library, not a complete
n8n instance; full reference-instance testing is still required for workflow parity.
See the pinned If/V2 implementation and workflow filter parameter module.

## Executed verification

`tools/studio_conditions_specimen.py --output NEW_DIRECTORY --node NODE_EXE
--modules NODE_MODULES` creates a bounded KPP satisfaction run over the real
candidate source. It establishes direct behavior, introduces a >= boundary
regression that passes the shallow case, rejects it on deeper consequences,
repairs it, and rechecks all prior cases with a separate native Node-RED runtime.
The native probe verifies actual routing, empty-branch suppression, strict Catch
errors and no partial output. It uses a new temporary userDir, no HTTP listener,
no resident flows and no inference provider. The full Community chase remains
unfinished regardless of the slice's result. Baker acceptance stays separate.

With a separately provisioned, owner-reviewed `n8n-workflow@2.46.4` directory,
pass `--reference PACKAGE_DIRECTORY` to include the matched filter gate. The
probe verifies the reference version and compiled filter source digest. No
reference dependency is installed automatically. The initial 229-case comparison
found ten numeric-empty mismatches; those failures were retained and corrected.
The expanded 281-case matrix then matched every selected boolean/error outcome.
This does not compare exact error messages, arbitrary expressions, all IF node
versions, UI fidelity, or all possible values. The native and earlier cases are
rerun cumulatively before the matched-reference gate is verified.

Private founding material, real Journals, credentials and imported sources remain
outside Git. The AppAI's full PRIMER, continuity, supervised MIND and eight-limb
composition must survive the chase. Full paired release suites, walkthroughs,
browser comparison and source promotion are separate release gates; a source
inventory or unit-test pass does not satisfy them.
