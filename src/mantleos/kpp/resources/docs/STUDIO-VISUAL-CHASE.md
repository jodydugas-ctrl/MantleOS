# Studio visual chase

The first Studio operator surface exposed a long form and raw JSON. Its functional
tests did not establish resemblance to a workflow canvas. The separate
`recipes/anchor-studio-visual-chase.json` adds explicit visual and interaction
obligations, preserving the original recipe and workspace pins.

The visual reference is the official n8n repository screenshot at
https://github.com/n8n-io/n8n/blob/master/assets/n8n-screenshot-readme.png
(retrieved 2026-11-03). Its navigation rail, workflow header, editor tabs, dotted
canvas, connected cards and separated detail areas guide the composition. This
does not change the selected Node-RED runtime into n8n, incorporate n8n code or
transfer its features, integrations or execution claims. Reference images stay
outside the release inventory; record their exact bytes using KPP gui-record.

The default Studio view now projects the actual canonical design on a canvas.
Select applications with pointer or keyboard, inspect responsibility, state and
guards, drag to arrange, zoom or fit, and explicitly save through the existing
revision check. Contracts contains typed links, portable import and advanced JSON.
Create new applications using the retained Node-RED Anchor palette and deliberately
review its draft; the Studio canvas does not execute workflows. Node-RED automation
remains at /red/. Verification retains the separately scoped calculator bake and
Baker action. AppAI activity shows the resident Heart and distinct limb identities;
the conversation panel keeps the supervised bridge visible beside the work.

Status and conversation use the existing Body endpoints. A decorative character,
canvas or successful screenshot comparison cannot establish mounted cognition.
Replies still await a supervised MIND and are released only after canonical commit.
No additional model call, inference provider or approval grant comes from this UI.
