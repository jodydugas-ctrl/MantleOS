# Mantle 2 implementation friction ledger

This is an append-only engineering ledger. Each event records the observed friction,
the local mitigation, and the platform change that would prevent recurrence.

| ID | Friction point | Mitigation used | Prevention / MantleOS change |
| --- | --- | --- | --- |
| FRICTION-001 | The requested isolated branches were not created by an earlier combined shell invocation, so work initially remained on `main`. | Verified each repository independently and created the exact local branches from the pinned SHAs before editing. | Bootstrap should assert branch name and base SHA before allowing a write. |
| FRICTION-002 | The checked-in virtual environments pointed at removed Python installations; system Python lacked project imports/dependencies. | Used `PYTHONPATH=src` with the available interpreter for stdlib Mantle gates; recorded missing product dependencies rather than installing globally. | Add a deterministic `mantle doctor` preflight that reports broken venvs and required local extras. |
| FRICTION-003 | The first generated 98-row matrix patch was rejected because generated rows lacked patch prefixes. | Re-issued the same content through `apply_patch` with valid hunk lines. | Add a patch-builder helper for generated tracked matrices and validate it before applying. |
| FRICTION-004 | The new resident loop initially had no shared typed contracts, so host integrations could drift into custom command dictionaries. | Added `mantle.contracts`, `ResidentRuntime`, typed fusion authorization, and canonical Body commands. | Ship resident runtime and dispatcher as the only maintained integration seam; certify command-contract version. |
| FRICTION-005 | Safe spore inspection could have printed embedded conversation/system-like text through the existing `read` command. | Added manifest-only `spore inspect`; raw conversation requires `--include-conversation` and the artifact is explicitly inert. | Make safe inspection the default public operation and require an explicit raw-content opt-in. |
| FRICTION-006 | Product-side terminal tests use placeholder nests and may not have Mantle importable, while live integrations must use the shared dispatcher. | Added a narrow standalone fallback and live dispatcher path; no global install was used. | Provide a pinned Mantle runtime fixture for product tests and make drift visible in status. |
| FRICTION-007 | Existing full-gate output is long-running and tool output can truncate, hiding final results. | Used bounded compile/focused commands and retained the final 109/109 result. | Stream child gate results to structured artifacts and expose partial/timeout states explicitly. |
| FRICTION-008 | Both checked-in virtual environments referenced Python installations that no longer existed; the new Python 3.14 venv initially lacked pip. | Preserved the old environments, created ignored `.venv-mantle2` environments, bootstrapped pip with `ensurepip`, and installed only declared local dependencies. | `mantle doctor` should validate interpreter targets, pip availability, version bounds, and optional extras before gates. |
| FRICTION-009 | The first Organize full-suite run pointed `--basetemp` at a child whose ignored parent did not exist, producing 30 setup errors unrelated to code. | Created the validated project-local artifact parent and reran; the suite reduced to the two real Windows failures. | Test launchers should create their contained artifact parent after path validation. |
| FRICTION-010 | Organize's shell test assumed Unix `touch` on Windows, despite Git for Windows already containing `touch.exe` outside the default command path. | Made the test use the platform's native shell operation (`type nul`) on Windows. | Cross-platform tests should select an operation by platform or invoke a project-local Python helper. |
| FRICTION-011 | `has_executable("dir")` expected a `cmd.exe` built-in to be discoverable through `shutil.which`, which only searches filesystem executables. | Added an explicit bounded Windows built-in registry consistent with the shell-action contract. | Define whether capability checks mean executable files or shell-resolvable commands and test both separately. |
| FRICTION-012 | Lifecycle authorization existed as a dataclass but was not on the hatch/graft mutation boundary, so it did not actually prevent activation. | Added one-shot authorization consumption, same-parent staging, phase journals, artifact/Stage-1 verification, atomic promotion, and external CLI enforcement. | Security contracts should have an acceptance test proving the public effectful entry point cannot bypass them. |
| FRICTION-013 | Pytest's user-global temp root and the repository's historical cache contained entries inaccessible to the current process, causing a setup error and cache warnings despite healthy tests. | Routed temporary state to unique contained `work/` or `.organize-appai/` bases and disabled the optional cache provider for the final Mantle suite. | Project gate launchers should always allocate a validated run-local temp/cache root and never depend on shared user-global pytest state. |
| FRICTION-014 | Running `prove`, `audit`, and `audit-mind` concurrently caused one proof to read a shared generated carrier while another gate was rewriting it, producing a transient `not a PNG file` failure. | Reran the proof serially and obtained `134/134`; final publication gates are serialized. | Gate fixtures should be unique per process or protected by atomic generation and process-safe coordination, and the CLI should document which gates are concurrency-safe. |
| FRICTION-015 | Lifecycle authorization became mandatory at the executable boundary, but several maintained README and guide examples still showed unauthenticated hatch/graft commands. | Audited maintained Markdown against the current CLI and updated examples to inspect, target-authorize, and then activate inert artifacts. | Keep security-sensitive command snippets in one generated or automatically checked source, and make documentation coherence part of the release gate. |
| FRICTION-016 | The Grimoire index and agent orientation described a v0.9-era section map and called the unversioned v0.9 mirror the single canonical file after v0.10 adoption. | Explicitly selected and read v0.10, preserved both immutable edition files byte-for-byte, and corrected the index/orientation to distinguish the adopted profile from compatibility artifacts. | Edition indexes should carry machine-checked section inventories, immutable hashes, adoption state, and compatibility-alias metadata. |
| FRICTION-017 | The independent `grimoire_tool.py` verifier accepts an edition path but implements v0.10 rules only, so invoking it against frozen v0.9 produced a large misleading failure report. | Added an upfront typed usage refusal for non-v0.10 editions, retained the v0.9 compatibility-test route, and documented both verification paths in the edition index. | Version-specific verification tools should reject unsupported editions immediately and name their supported profile in CLI help and documentation. |
| FRICTION-018 | The documented germ-v2 carrier contract existed while the executable hatchery still accepted the legacy germ schema. | Made `mantle-germ-v2` the only activatable germ, added explicit inert migration, and regenerated maintained spores and eggs. | Add a schema-conformance invariant that compares public format constants, hatch validation, fixtures, and migration documentation. |
| FRICTION-019 | Removing Organize.AppAI's duplicated terminal fallback exposed tests that used a dummy directory instead of a valid resident. | Replaced dummy nests with residents born and persisted by Mantle, then asserted shared dispatcher and runtime receipts. | Ship a canonical integration-resident fixture for all host adapters and prohibit mock directories at protocol-boundary tests. |
| FRICTION-020 | The Organize demo assumed a Unix `cygpath` environment, while invoking `bash` on Windows could select WSL rather than Git for Windows. | Added feature detection for `cygpath` and `wslpath` and ran the acceptance demo with an explicit Git Bash executable. | A Windows launcher should identify its shell/runtime up front and print the resolved interpreter before touching fixtures. |
| FRICTION-021 | The first release scan reported secret-shaped test sentinels, bytecode caches, and historical absolute paths as leaks. | Limited the release scan to Git-tracked content, split credential-shaped invariant sentinels, and removed the remaining private workspace path from tracked prose. | Maintain typed scan exclusions for generated binaries and construct secret-test sentinels without storing publishable credential shapes. |
| FRICTION-022 | Organize's existing virtual environment still imported Mantle 1.5 during a demo even though the product dependency was pinned to Mantle 2. | Kept the result as non-release evidence and required final demos to bind explicitly to the release candidate source or clean installed wheel. | `mantle-status` and release launchers should fail closed when installed version, source commit, or resident protocol differs from the declared product pin. |
| FRICTION-023 | The package build completed and produced both distributions, but deprecated license-table warnings on stderr made the local PowerShell capture report a nonzero wrapper result. | Migrated package metadata to SPDX `MIT` with an explicit license file and validated artifacts independently with Twine and a clean install. | Release launchers should preserve the child exit code separately from stderr capture, and packaging warnings should be treated as tracked pre-release defects. |
| FRICTION-024 | The first `Start-Process` package wrapper embedded path concatenation directly in redirection arguments, which PowerShell parsed as stray positional arguments. | Resolved the executable, repository, stdout, and stderr paths into explicit variables before invoking the process; the child then returned a reliable exit code. | Check in one cross-platform release runner instead of reconstructing shell-specific redirection syntax during a release pass. |
| FRICTION-025 | Organize's fresh application certification failed because its local venv lacked Pillow, while the CLI exposed only the aggregate `repository-invariants` failure. | Ran the registry to identify `SPORE-2`, installed the pinned Spore extra locally, certified a new preserved rebind, and changed certification errors to name each failed invariant with bounded diagnostic detail. | `mantle doctor` should preflight certification extras, and aggregate gates must surface leaf failure codes and details in their primary refusal receipt. |
| FRICTION-026 | The bundled GitHub CI inspection helper crashed while decoding Actions logs with the Windows cp1252 codec. | Retrieved the failing job directly with `gh run view --log-failed` after forcing console and pipeline output to UTF-8. | CI inspection helpers should always decode subprocess output as UTF-8 with replacement and test logs containing C1/ANSI bytes on Windows. |
| FRICTION-027 | The package smoke printed top-level help but returned exit 2; a local PowerShell command sequence continued and let a later successful version check mask that intermediate failure. | Made `-h`, `--help`, and `help` return 0, added a direct return-code regression, and retained `1` for unknown commands. | Release smoke steps should use fail-fast wrappers and assert each command's exit code independently on every supported shell. |
| FRICTION-028 | The local Windows account could not create symlinks, while GitHub's Windows runner could and exposed a `PERSIST-1` claim that applied the POSIX descriptor-swap proof to the non-descriptor Windows fallback. | Kept all Windows traversal and pre-existing symlink refusals, scoped the concurrent parent-swap invariant to platforms with secure dir-fd operations, and documented the trusted-operator residual risk. | Platform security invariants must declare the OS primitive they depend on and CI must include a runner that actually exercises each admitted platform capability. |
| FRICTION-029 | A context-light patch changed the first of two `if linked_nest_created` branches, so the root-symlink test referenced the later `persist_module` import and crashed only on a symlink-capable runner. | Used occurrence inspection to restore the unconditional root-symlink refusal and apply the platform-capability guard only to the parent-swap simulation. | Patches against duplicated conditions should include semantic surrounding context, followed by an occurrence search and execution on the capability-bearing CI platform. |
