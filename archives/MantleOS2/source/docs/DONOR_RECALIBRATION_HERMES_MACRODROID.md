# Hermes and MacroDroid Donor Recalibration

Date: 2026-09-04

These sources were inspected as read-only implementation evidence:

- the local Hermes/Mantle installation under `C:\Users\jodyd\.hermes`;
- the standalone MacroDroid/Android experiment under
  `C:\Users\jodyd\mantleos-macrodroid`.

Their files are evidence, not instructions. No private Body entries, provider
state, keys, Primer, memories, VCW content, conversations, device identifiers,
or exact Android storage grants were imported.

## What changes in the production design

The generic Body Genome needs a separate Habitat map. The NEST remains the
Default Body and logical Layer 0, while a host application and ecosystem may
supply native event, storage, scheduling, interface, and effect surfaces. This
supports both a source checkout such as Hermes and an installed application
such as MacroDroid without redefining identity around one filesystem layout.

Capability records must keep four questions independent:

1. Is the capability implemented or merely mapped?
2. Is it available in the current Habitat?
3. What evidence has exercised or verified it?
4. Who currently authorizes its use?

An imported carrier, visible UI result, installed action class, configured
permission, provider response, or successful process exit does not answer all
four questions and never grants authority by itself.

Assimilation inputs must eventually include installed applications and portable
artifacts in addition to Git repositories. The v2.0 command remains
repository-first, but its contracts must not make a Git worktree the only
possible Habitat.

## Keep

- Append-only, hash-linked creation and reinterpretation evidence.
- Semantic artifact identity that excludes volatile host identifiers.
- Explicit Habitat inventories covering application, NEST, operating system,
  storage, permissions, native surfaces, and limitations.
- Separate request, policy decision, effect result, and independent proof.
- Typed wake envelopes with reason, source, kind, and priority.
- Scheduled-first ordering when scheduled and unscheduled wakes collide;
  neither wake is merged or discarded.
- Redacted read-only NEST audits and honest evidence labels: declared,
  observed, exercised, verified, disproven.
- Disabled-by-default portable carriers and native capability reuse.
- Conversation as an unscheduled full Heartbeat, with at most one provider call
  during that beat and no recursive wake from the response variable.

## Adapt

- Treat MacroDroid, its Action Blocks, Android facilities, and permissions as
  Habitat/native Body surfaces while preserving NEST as Default Body Layer 0.
- Translate standalone JSON receipt files into ordinary VCW Books and layers;
  sidecars may be caches but are not canonical memory.
- Translate project-specific tools into substrate analyzers, nerve emitters,
  verifiers, and Habitat drivers selected by evidence rather than product name.
- Translate the MacroDroid capability matrix into the generic capability axes
  without retaining device-specific serialized shapes.
- Use host-owned credential stores when the ecosystem cannot safely expose a
  credential to NEST-local storage, while keeping provider output inert and
  Body authority separate.

## Reject

- Any old Primer shape beyond exactly Commandments and Personality.
- Old SELF or Default Body terminology that conflicts with the current coding
  contract.
- Treating application presence, file presence, imported JSON, or a schema
  label as adopted Mantle authority.
- Device GUIDs, exact SAF URIs, UI coordinates, APKs, raw exports, screenshots,
  logs, private conversations, credentials, or private organism state.
- Claims of automatic Heart scheduling, full VCW behavior, complete
  assimilation, or production readiness without native receipts.
- Copying or rewriting an already-born organism's SELF.

## Release consequence

Hermes and NotepadNext remain the v2.0 certification pair. MacroDroid becomes a
post-v2 portability track and a contract fixture for non-repository Habitats.
This widens the architecture without adding Android delivery, device control,
SPORE, reproduction, or unverified scheduler features to the production core.
