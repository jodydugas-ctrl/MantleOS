# Security boundaries

This alpha is a deterministic application framework, not an operating system
security boundary or a sandbox for hostile Python. A trusted local operator can
invoke its APIs and alter files. MIND separation depends on exposing only the
bounded proposal interface to the model.

Checked effects separate intent, permission, attempt, observation, and
verification. Exceptions after dispatch can leave an UNKNOWN effect; they must
not trigger blind retries. Program requests use explicit replay identifiers.
Admission rechecks candidate hashes and the current Body revision.

Cartridge, Chroma, and local archive checks establish structural integrity and
detect inconsistent content. They do not authenticate an unknown publisher or
encrypt personal data. Do not automatically run code from an imported carrier.
Legacy encrypted Book/RGBA readers have been removed; no encryption guarantee
is supplied by either current carrier.

Filesystem locks and staged replacement cover cooperating local writers.
Interrupted Body publication requires explicit recovery and retains evidence.
No hostile-filesystem, distributed transaction, network-filesystem, or power-loss
durability guarantee is claimed. Windows and POSIX have different filesystem
flush semantics. Keep independent backups of valuable state.

The supplied storage module retains opt-in network snapshot functionality for
explicit snapshot publication. It is not part of this release's qualified path. Live cloud sync,
OS services, arbitrary generated-code execution, and paid providers are not
enabled by the demo or tests. The local continuity simulator is not a remote
service, authentication scheme, or multi-host certification.

Report suspected vulnerabilities privately to the project owner through an
existing trusted channel. Do not include real keys, private memory, or persona
material in an issue or test fixture.

AppAI mission policy is operator-owned local state. It scopes the cooperating
scanner process, not arbitrary code running under the same Windows account.
The child inherits no credentials, parent experience, or authority database.
Portable transport never authorizes destination execution. Revocation prevents
further local dispatch/admission; it cannot retract work on an external host.
Mutable hostile filesystems and remote agents need stronger isolation and a
separate authenticated protocol before deployment.

Host connections retain only bounded semantic metadata by default. Addressed
`@appai` user text is explicitly committed; raw tool arguments and assistant
responses are not retained by the default event listeners. Tool grants are an
additional restriction, and Hermes' own authority checks still apply. If Mantle
authority is unavailable, an addressed AppAI tool action is denied. Native
Hermes behavior remains independent. See the example guide for private paths.
